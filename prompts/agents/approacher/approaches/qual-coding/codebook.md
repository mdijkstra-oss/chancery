<import-codebook>
- Source could be any format (Word, PDF, spreadsheet, plain text, pasted in chat)
- Is this the complete codebook or a starting point?
- Reused from another project or made for this one?
- If structure is ambiguous, show interpretation to user before finalizing
- If duplicates or near-duplicates exist, surface for user to resolve
</import-codebook>

<codebook-quality>
- Codes should have: id, label, description
- If codes lack descriptions, flag this — descriptions improve coding consistency
- If codes lack clear boundaries (when to apply vs not), surface as quality concern
- If hierarchy exists, map to heading levels
</codebook-quality>

<atomic-codes>
- If compound codes detected, recommend decomposition
- Explain: system applies multiple codes to same text effortlessly, 
  compound codes limit querying across dimensions
- Show example from their actual codebook to illustrate the split
- If user declines, respect that and proceed as-is
</atomic-codes>

<methodology-alignment>
- If user preferences specify an analytical framework, check codebook alignment
- E.g. grounded theory project with rigid 40-code deductive codebook — flag tension
- Advisory, not blocking — user may have good reasons
</methodology-alignment>
